# Лабораторная №4 — Angular

Клиент построен на standalone-компонентах Angular. `AuthStore` хранит глобальное состояние в Signals, `authInterceptor` добавляет JWT и обновляет истёкший access-токен через refresh. `StudentSearch` использует RxJS `switchMap`, чтобы отменять устаревшие запросы; ввод фильтра проходит через `valueChanges` и `debounceTime`. Все данные загружаются из Java API лабораторной №3. Выход отзывает refresh-токен на сервере.

## Запуск

Из корня репозитория: `docker compose up --build`. Затем откройте `http://127.0.0.1:5500/login`. Angular собирается в первом этапе Dockerfile и раздаётся Nginx во втором. Nginx направляет `/api/` в контейнер `api`, а остальные пути — в `index.html` для клиентской маршрутизации.

Для разработки: `npm ci && npm start` в этом каталоге. При отдельном запуске Angular настройте proxy для `/api` или используйте Docker Compose. Настройки портов и секретов находятся в корневом `.env` (образец `.env.example`).

## Структура

- `core/auth.ts` — авторизация, JWT, обновление токена и защита маршрутов;
- `core/students.ts` — запросы к студентам;
- `core/student-search.ts` — повторно используемый реактивный поиск;
- `core/errors.ts` — сообщения об ошибках API;
- `pages/` — страницы входа, регистрации, профиля, списка, карточки и формы; строка списка — отдельный компонент с `@Input` и `@Output`;
- `styles.css` — общий адаптивный интерфейс.

Обычный пользователь только просматривает студентов. Администратор может создавать, изменять и удалять записи. Права проверяются также сервером.

Команда `npm start` использует `proxy.conf.json` и пересылает `/api` на Java API по `127.0.0.1:8000`.
