# Лабораторная №5 — AnalogJS на Angular

AnalogJS добавляет к компонентам лабораторной №4 файловые маршруты, SSR и серверный middleware. Сами страницы продолжают использовать отдельные `.ts`, `.html` и `.css`. Java API лабораторной №3 остаётся источником данных и единственным местом бизнес-логики.

## Запуск

Из корня репозитория: `docker compose up -d --build`. Сайт: <http://127.0.0.1:5500/login>. Docker собирает клиент и сервер AnalogJS, затем запускает Nitro на порту 3000 внутри контейнера. Переменная `API_URL` указывает на Java API внутри Docker; браузер обращается к тому же адресу сайта через `/api/`.

Для разработки в этом каталоге: `cp .env.example .env`, укажите в `.env` адрес Java API в `API_URL`, затем выполните `npm ci` и `npm start`. `npm run build` создаёт клиентскую и серверную сборки, `npm run preview` запускает готовый сервер. При запуске через Docker адрес задаётся корневой переменной `ANALOG_API_URL`.

## Основные файлы

- `vite.config.ts` включает потоковый SSR и сборку Nitro. Первая порция списка рендерится сервером, затем Angular подключается к HTML.
- `src/app/pages/*.page.ts` задают маршруты; `src/app/pages/students/[id].page.ts` задаёт карточку студента, а `[...not-found].page.ts` — страницу 404.
- `src/app/app.ts` содержит только оболочку и место для текущей страницы; `src/app/components/site-header/` содержит общую шапку.
- `src/app/pages/` содержит файлы маршрутов `.page.ts` и отдельную папку с `.ts`, `.html`, `.css` для каждой страницы.
- `src/app/components/` содержит переиспользуемые фильтры, список и строку таблицы. Каждый компонент хранит логику, разметку и стили в своей папке.
- `src/app/models/` описывает данные студента и пользователя; `src/app/services/` содержит запросы, авторизацию, поиск и синхронизацию вкладок.
- `src/server/middleware/auth.ts` направляет посетителей без сессии на вход и запрещает общему кешу хранить личный HTML.
- `src/server/routes/api/[...path].ts` пересылает API-запросы в Java без дублирования правил работы со студентами. `src/server/api-url.ts` читает адрес Java API из `API_URL`.
- `src/app/services/server-api.ts` передаёт cookies из входящего запроса при серверном получении данных.
- `src/app/services/students.ts` запрашивает порции студентов и хранит кратковременный кеш списка. Селектор задаёт 10, 20, 50 или 100 записей на странице. В режиме «Все» записи подгружаются по 100 штук при прокрутке. Успешные изменения сбрасывают кеш; `student-changes.ts` обновляет открытые вкладки.

Авторизация основана на `HttpOnly` cookies. JWT не включаются в HTML и не сохраняются в `localStorage`. Изменяющие запросы защищены CSRF-заголовком. До двух заполненных фильтров список идёт через GET, начиная с трёх — через QUERY с JSON-телом. Обычный пользователь просматривает студентов, администратор может изменять записи; Java проверяет права повторно.
