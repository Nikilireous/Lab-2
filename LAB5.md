# Лабораторная №5 — AnalogJS

## Что изменилось после лабораторной №4

Клиент по-прежнему использует компоненты Angular и те же формы и стили. AnalogJS добавляет серверный рендеринг, маршруты из файлов и серверный middleware. Java-приложение остаётся единственным местом, где проверяются JWT, права, правила для студентов и выполняются операции с PostgreSQL. Сервер AnalogJS подготавливает HTML и пересылает `/api/` на Java API.

## Как объяснить запрос на защите

1. Браузер запрашивает `/students` у AnalogJS.
2. Middleware проверяет наличие cookie сессии и перенаправляет неавторизованного посетителя на `/login`.
3. AnalogJS рендерит страницу на сервере; Angular затем подключается к готовому HTML (hydration).
4. Список запрашивается у Java API страницами. При двух и менее фильтрах используется GET, при трёх и более — QUERY с JSON.
5. Создание, правка и удаление идут только через Java API. Сервер повторно проверяет роль администратора и данные независимо от видимости кнопок.
6. Access и refresh JWT хранятся в `HttpOnly` cookies. При изменяющих запросах передаётся CSRF-заголовок.

## Соответствие заданию

| Требование | Где искать |
| --- | --- |
| AnalogJS и SSR | `angular-frontend/vite.config.ts`, `angular-frontend/src/main.server.ts` |
| Файловые маршруты, включая `/students/[id]` | `angular-frontend/src/app/pages/*.page.ts`, `angular-frontend/src/app/pages/students/` |
| Защита и редирект | `angular-frontend/src/server/middleware/auth.ts`, `angular-frontend/src/app/core/auth.ts` |

| Docker | `compose.yaml`, `angular-frontend/Dockerfile` |

## Масштабирование и его пределы

Список всегда выдаётся страницами: по умолчанию 20, максимум 100 студентов за запрос. Это предотвращает загрузку всей таблицы в память API и браузера. ИСУ ID — первичный ключ; дополнительные индексы обслуживают распространённые фильтры по ФИО, группе, общежитию и комнате, дате заселения. Запросы с подстрочным поиском (`%текст%`) и очень глубокие страницы могут оставаться дорогими; для них понадобится отдельная настройка PostgreSQL и измерения на реальном объёме данных.

Формат ИСУ ID в проекте — шесть цифр, первая ненулевая. Это даёт максимум 900 000 разных студенческих записей. Цель в миллион **пользователей** также нельзя гарантировать по одному исходному коду: фактический предел зависит от числа экземпляров приложения, ресурсов PostgreSQL, характера запросов и результатов нагрузочного теста. В этой лабораторной реализованы ограничения ответа и индексы, а не заявлена непроверенная пропускная способность в миллион одновременных соединений.

## Проверка

Из корня репозитория: `docker compose up -d --build`, затем открыть `http://127.0.0.1:5500/login`. Для проверки API на изолированной временной базе выполнить `bash scripts/test-docker.sh`. После запуска можно проверить редирект прямым открытием `/students` без входа, вход, просмотр `/students/123456`, редактирование под администратором, страницу с неизвестным адресом и повторную загрузку после изменения студента.
