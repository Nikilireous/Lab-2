# Лабораторные работы по веб-программированию

В `JS/` хранится исходный клиент лабораторной №1, в `django/` — сервер лабораторной №2, в `java-backend/` — Jakarta EE API лабораторной №3, в `angular-frontend/` — Angular-клиент лабораторной №4, перенесённый на AnalogJS в лабораторной №5. Все исходники находятся в одном репозитории. Исходное состояние четвёртой лабораторной сохранено в ветке `lab4-angular`.

## Запуск лабораторной №5

1. Скопируйте `.env.example` в `.env` и замените пароли и `JWT_SECRET`. Если `.env` уже есть, сохраните существующие значения: в нём подключение к вашей базе.
2. Выполните `docker compose up -d --build`.
3. Откройте [AnalogJS-клиент](http://127.0.0.1:5500/login) и [Swagger UI](http://127.0.0.1:8081/). API доступно на <http://127.0.0.1:8000/api/>.

AnalogJS использует адрес `/api/` и пересылает запросы на Java-сервер. JWT находятся в HttpOnly cookies, а изменяющие запросы защищены CSRF-заголовком. Данные PostgreSQL хранятся в Docker volume. `docker compose down` останавливает контейнеры и сохраняет базу.

Для DBeaver: PostgreSQL на `127.0.0.1:5433`, база `students_lab3`, пользователь `lab3`, пароль `DB_PASSWORD` из корневого `.env`. Внутри Docker API подключается к `db:5432`.

Обычный запуск поднимает AnalogJS, Java API, PostgreSQL и Swagger. Исходники прежних лабораторных остаются в `JS/` и `django/`. Пути сборки, порты, образы, адреса и секреты задаются в корневом `.env`; образец — `.env.example`. Для сохранения существующих данных значение `DB_VOLUME_NAME` должно указывать на уже используемый том базы.

`bash scripts/test-docker.sh` проверяет Java API на **отдельной временной базе** и удаляет её после теста. Подробности реализации: [AnalogJS-клиент](angular-frontend/README.md), [Java-сервер](java-backend/README.md).
